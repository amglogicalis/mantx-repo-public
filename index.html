💡 ¿Qué es MANTX?

MANTX es un motor autónomo de entrenamiento, evaluación comparativa y despliegue de modelos de Inteligencia Artificial que opera con coste $0 absoluto aprovechando los recursos gratuitos del ecosistema de desarrollo moderno (GitHub Actions, GitHub Releases y HuggingFace).

🔑 Requisitos y Credenciales:

  • GitHub PAT (Personal Access Token): Imprescindible para orquestar workflows de 6h en Actions y versionar adaptadores de pesos (hasta 2GB por release).
  • Modelos Locales Sub-4B: Corren sin coste alguno en CPU dentro de GitHub Actions (Llama 3.2, Qwen 2.5 Coder, SmolLM2, Phi 3.5).
  • HuggingFace Token (Opcional): Si dispones de token HF, puedes desplegar en Spaces ZeroGPU o solicitar el grant gratuito para GPUs sin coste.
  • BYOK (Bring Your Own Keys): Puedes agregar claves de Groq, Gemini, DeepSeek o OpenAI al gateway AKG para mitigar errores 429.

🔄 Ciclo de Vida Completo (Closed-Loop)

1. Model Selection: Explora el Marketplace y planifica el hardware target (CPU, ZeroGPU o Cloud).
2. Synthetic Data Forge: Sintetiza datasets de alta calidad con Constitutional AI o genera semillas con ayuda de IAs externas.
3. Nimphys Laboratory: Lanza matrices comparativas entre métodos (QLoRA, LoRA, RAFT) para hallar la mejor convergencia.
4. Deimatic Battles: Enfrenta candidatos con o sin Graph RAG para evaluar precisión y coherencia en tiempo real.
5. Production Intelligence (Auto-Heal): Al activarlo, el sistema detecta caídas de calidad (drift) y reentrena automáticamente el modelo desplegado.
6. Mantx Code CLI: Agente autónomo en terminal que utiliza tus propios Nimphys entrenados como cerebro de desarrollo.

📚 Guía de Entrenamiento: Archivos, Requisitos y Buenas Prácticas

Cada método de entrenamiento persigue un objetivo distinto. Conoce qué archivos necesitas como mínimo, cuál es la combinación óptima para lograr la máxima precisión y qué errores comunes debes evitar.

📦 Requisitos de Entrada por Tipo de Entrenamiento:

1. QLoRA / LoRA (PEFT Clásico) Instrucciones / SFT
• Mínimo Requerido: Un Dataset estructurado (.json) con pares de instruction / output (formato Alpaca o ShareGPT).
• Para un Buen Entrenamiento: Entre 500 y 3.000 ejemplos de alta diversidad con razonamiento paso a paso (Chain of Thought). Si subes documentos, se procesarán como adaptación de dominio continua, pero la capacidad dialógica la aportará el dataset.
2. RAFT (Retrieval-Augmented Fine-Tuning) Lectura de Documentos
• Mínimo Requerido: Dataset (.json) + Documentos (.md, .txt, .pdf, .sql). Ambos son indispensables.
• Para un Buen Entrenamiento: Documentos técnicos bien estructurados por secciones, acompañados de preguntas del dataset que requieran consultar y citar fragmentos de esos documentos para responder correctamente.
3. Graph RAG (Arzor) & Memoria Ecdysis Cero Alucinaciones
• Mínimo Requerido: Documentos crudos, especificaciones, código o manuales. No requiere dataset de QA.
• Para un Buen Entrenamiento: Archivos ricos en entidades técnicas, tablas, esquemas y relaciones lógicas. El motor extrae el grafo semántico y genera embeddings para consulta viva en inferencia.
4. AFT (Adaptive Fractal Tuning) Especialización Fractal $0
• Mínimo Requerido: Un Perfil Canónico AFT (.json o .yaml) diseñado y exportado desde el AFT Visual Studio.
• Para un Buen Entrenamiento: Las 5 capas fractales completas: system_instructions (≥300 caracteres de arquitecto sénior), entre 10 y 15 ejemplos few-shot con razonamiento interno (reasoning), reglas de estilo estrictas, límites de dominio y palabras clave RAG. No modifica pesos: especializa operativamente con coste $0.

✔ Buenas Prácticas Recomendadas

  • Calidad sobre Cantidad: 500 ejemplos limpios con explicaciones detalladas superan a 20.000 ejemplos breves, ruidosos o repetitivos.
  • Estructura de Salida Homogénea: Si entrenas un modelo para programar, asegúrate de que todos los outputs del dataset sigan el mismo formato de markdown y comentarios.
  • Habilitar Graph RAG para Datos Exactos: Si tu modelo debe manejar esquemas SQL, números de versión o sintaxis estricta, activa siempre Graph RAG para evitar alucinaciones.
  • Validar en el Laboratorio: Antes de desplegar, pasa tu configuración por Nimphys Laboratory Matrix para certificar que el Loss converge por debajo de 0.50 y el score supera 90/100.

✘ Malas Prácticas a Evitar

  • Entrenar LoRA solo con Documentos Crudos: Pasar PDFs o texto plano sin dataset de preguntas/respuestas creará un modelo que memoriza frases pero no sabe responder preguntas ni seguir instrucciones.
  • Respuestas Telegráficas o Vacías: Evita datasets con respuestas como "OK", "Sí" o código sin contexto, ya que dañan la coherencia del modelo.
  • Sobreajuste (Overfitting): Entrenar demasiados pasos sobre datasets muy pequeños provocará que el modelo solo memorice de memoria y falle ante preguntas nuevas.
  • Confiar en PEFT Puro para Datos Numéricos Críticos: La memoria paramétrica es difusa; para constantes, endpoints o documentación cambiante, usa siempre RAG o Memoria Ecdysis.
🌐 Integración con Termes Symbiont: Regla Estricta Mono-Provider & Mono-Modelo
⚠️ Arquitectura Sin Conflictos

Al conectar un endpoint de Termes Symbiont (sea mediante URL local http://127.0.0.1:7420/v1 o archivo de endpoint dedicado .json / ep_pub_*), es fundamental e imprescindible que el endpoint esté configurado como Mono-Provider y Mono-Modelo.

⚠️ ¿Por qué se producen conflictos si no es mono-modelo?
Si un endpoint expone múltiples proveedores heterogéneos o mezcla modelos distintos en la misma ruta, se originan colisiones en el formateo de tokens, discrepancias en el schema de mensajes, desbordamientos de context window y fallos impredecibles en el entrenamiento o inferencia.
✔ Configuración Óptima Recomendada:
Vincula cada endpoint a un único modelo base y un único proveedor específico (ej: gemini-3.7-flash con Google Gemini Web). MANTX detectará automáticamente el archivo de endpoint mono-modelo y lo aislará para garantizar 100% de estabilidad y reproducibilidad.

¿Qué es Auto-Heal & Closed-Loop Recovery?

Motor autónomo de recuperación de calidad para modelos en producción.

💡 Concepto y Propósito Auto-Heal es un circuito cerrado (Closed-Loop) que monitoriza continuamente las inferencias y la similitud semántica de tus Nimphys en producción frente a su baseline de calidad certificada. Si el rendimiento o la coherencia caen, el sistema se autorepara automáticamente sin intervención humana y a coste $0.
🔄 ¿Cómo Funciona el Ciclo Autónomo?
  1. 1. Detección de Drift: MANTX audita la distancia semántica y latencia frente a las respuestas esperadas del baseline.
  2. 2. Disparo por Umbral: Si la desviación supera el umbral configurado individualmente en el modelo (ej: 12%), se activa la recuperación.
  3. 3. Síntesis de Datos Focalizada: Synthetic Data Forge genera automáticamente ejemplos de entrenamiento específicos con Constitutional AI para reforzar los puntos ciegos.
  4. 4. Re-entrenamiento Incremental ($0): Se orquesta un workflow en GitHub Actions para compilar la nueva versión de pesos (ej: v1.1.0 → v1.2.0).
  5. 5. Deimatic Battle de Validación: Enfrenta el nuevo candidato contra el modelo en producción. Solo se despliega si supera en score y calidad al modelo actual, garantizando cero regresiones.
🔑 Requisitos Previos • GitHub PAT: Necesario para que MANTX lance los workflows de re-entrenamiento en GitHub Actions.
• Nimphy en Producción: Tener al menos un modelo con baseline de calidad establecida.
